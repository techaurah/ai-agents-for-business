# Glossary

Every term this course uses, in plain language. If a lesson uses a word that is not defined here or in the lesson itself, that is a lesson problem: please open an issue.

**Acceptance set**: A saved set of test cases with expected outcomes that an agent must pass before it touches real customers, and after every change (Lesson 20).

**Agent**: Software that takes a goal, decides steps toward it using a model, uses tools to act, and checks its own progress, inside limits a human set (Lesson 01).

**Agent as a Service (managed agent)**: An agent designed, built, deployed, monitored, and improved by an outside provider for a recurring fee, under a scope the business approves (Lesson 08).

**Baseline**: The measured performance of the current, human way of doing a process, taken before any automation, so a pilot has something honest to beat (Lesson 13).

**Chatbot**: Software that answers in conversation, usually from a fixed set of intents or a knowledge base, without deciding multi step actions of its own (Lesson 01).

**Deployment plan**: The capstone artifact: readiness audit, pilot design, oversight plan, and scorecard for one chosen process (Lesson 26).

**Escalation**: Handing a case from the agent to a named human, with the context attached, under rules written in advance (Lesson 15).

**Escalation policy**: The written rules for when an agent acts, drafts for approval, asks, or escalates, by risk and confidence (Lesson 15).

**Framework**: A code library (LangGraph, CrewAI, and others) that gives builders the loop, state, and tool wiring for agents. A builder concern; buyers evaluate what it makes possible and what it locks in (Lesson 09).

**Human in the loop**: A design where a person approves, edits, or rejects agent work at defined points, rather than discovering it afterwards (Lesson 15).

**Least privilege**: Giving an agent, or a person, only the access its job needs, nothing more (Lesson 06).

**Operator**: The named person who supervises an agent day to day: reviews its queue, handles escalations, and owns its scorecard (Lesson 07).

**Pilot**: A time boxed, scope boxed trial of an agent on real work, designed in advance to answer one question: is this worth scaling (Lesson 12)?

**Prompt injection**: An attack where text the agent reads (a message, a document, a web page) carries instructions meant to steer it. Defence is limiting what a steered agent can do (Lessons 16, 28).

**Readiness**: Whether data, access, and people are each fit for an agent to start: the three sections of the readiness audit (Lessons 05 to 07).

**Scorecard**: The one page record of a pilot or a month: volume, quality, escalations, cost, and the verdict they support (Lessons 22, 26).

**Simulator (twin)**: This course's term for a standard library model of a business process: real shapes and rules, invented data, runnable and testable offline.

**Total cost of ownership**: Build cost plus run cost plus supervision cost plus the cost of fixing mistakes, over the same period, with assumptions stated (Lesson 11).

**Unit economics**: The cost and value of one handled unit of work, one enquiry, one ticket, one booking, computed the same way for the agent and for the manual process (Lesson 23).

**Vendor evaluation**: A scored, evidence based comparison of providers or platforms against criteria chosen before the demos, not after (Lesson 10).

**Workflow automation**: Fixed steps connected in a fixed order, where software follows rules a human wrote and makes no judgement calls between steps (Lesson 01).
